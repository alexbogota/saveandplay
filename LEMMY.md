# Lemmy: всё про эту площадку

Создано 11 октября 2026. Вернуться: [START.md](START.md), [docs/channels.md](docs/channels.md). Решение записано в `docs/decisions.md` (запись «Lemmy как новая площадка»).

## Статус
Код, настройки, расписание и тесты готовы. **Всё выключено**: `autopost: false`, все сообщества `enabled: false`. Программа ни разу не работала с настоящим сервером Lemmy (из рабочей среды его не достать), тесты идут на подделке сервера по описанию API. Поэтому первый шаг после создания аккаунта: Actions → Post to Lemmy → mode `check`.

## Что публикуется
То же, что в Nostr (так владелец понял «новости»): скидка дня и статьи сайта. Чужие новости не репостим.
- **Скидка** (`--kind deal`), раз в день в 07:00 по Боготе: первая скидка брифа из блока `lemmy` в `data/accounts.json` (GOG и IndieGala, от 50%). Заголовок `Игра: -85% at Магазин ($цена, was $старая)`, ссылка на НАШУ страницу игры (`utm_source=lemmy-prices`), в тексте цена, дата проверки, конец акции, «Why today», обложка как картинка с alt-текстом, последней строкой `Ad: we may earn a commission if you buy.`
- **Статья** (`--kind article`), в 12:30, не чаще раза в 2 дня (`articleEveryDays`): самый старый ещё не выложенный гид, только если его страница открывается. Заголовок и описание из шапки гида, картинка с `imageAlt`. Пометки `Ad` нет: гид ведёт на наш сайт. Не пускать гид в Lemmy: `lemmy: false` в шапке.
Текст собирает программа по шаблону, без нейросети. Цифры только из `data/deals.json` через бриф.

## Правила сообществ (проверено 11 октября, ЧИТАТЬ ПЕРЕД ВКЛЮЧЕНИЕМ)
У каждого сообщества свои правила, нарушение = удаление поста и бан аккаунта. Выбор сообществ лежит в `data/lemmy-accounts.json`, не в коде.

| Сообщество | Что нашёл | Вывод |
|---|---|---|
| gamedeals@lemmy.world (5400) | запрещены партнёрские ссылки, нужны прямые ссылки в магазин, правило 2:1 для самопродвижения | НЕ подходит для скидок |
| pcgaming@lemmy.world, pcgaming@lemmy.ca | запрещена реклама | не подходят (и для статей) |
| gamedeals@compuverse.uk (700) | партнёрские ссылки разрешены, если указаны; только нормальные магазины | подходит для скидок; боковую панель сайт закрыл для роботов, прочитать самому |
| gamedeals@lemmy.zip (3700) | в описании только рекомендуемый формат заголовка | самое живое; прочитать панель и правила сервера |
| steam@lemmy.world (800) | описание «For Steam Game Stuff», правил не нашёл | вариант для гидов про Steam |

В настройках три из них записаны выключенными (`note` рядом объясняет, откуда вывод). Включать по одному: прочитать боковую панель, `enabled: true`, пробный запуск, потом `autopost: true`. Серые ключи (Kinguin) в Lemmy не идут. По `docs/channels.md` §5 Lemmy нужно добавить площадкой в Admitad и Sovrn до включения скидок.

## Что делает владелец (один раз)
1. Создать аккаунт на сервере (по умолчанию в настройках `lemmy.zip`, можно другой). Сервер просит заявку, e-mail и капчу, это человеческий шаг. Двухфакторный вход НЕ включать: бот его не умеет.
2. В `.env` добавить строку `LEMMY_PASSWORD=пароль`, выполнить `npm run lemmy:secret` (пароль уйдёт в GitHub, на экране не показывается).
3. В `data/lemmy-accounts.json` поправить `instance` и `username` (сейчас заглушки `lemmy.zip` и `saveandplay`).
4. Попросить Claude Code закоммитить настройки Lemmy. Workflow уже на месте: `.github/workflows/post-lemmy.yml` (перенесён 12 октября), кнопка Post to Lemmy на GitHub есть.
5. GitHub → Actions → Post to Lemmy → Run workflow → mode `check`: должен показать версию Lemmy, вход, каждое сообщество. Потом mode `profile`: имя, описание, значок BOT, картинки.
6. Включить сообщества и `autopost` как описано выше. Перед включением mode `dry-run` покажет готовые тексты ничего не публикуя.

## Как устроено
- `data/lemmy-accounts.json`: сервер, имя, сообщества, профиль, `autopost`. `data/accounts.json`, блок `lemmy`: правила подбора скидок для брифа. Ключи должны совпадать.
- `scripts/lib/lemmy.mjs` клиент и шаблоны, `scripts/post-lemmy.mjs` постинг, `scripts/lemmy-check.mjs` проверка и профиль, `scripts/lemmy-secret.mjs` пароль в GitHub, `scripts/test-lemmy.mjs` тесты (`npm run lemmy:test`).
- API: программа сама определяет версию (сначала v4 = Lemmy 1.0, потом v3 = Lemmy 0.19, на 11 октября стабильная версия 0.19.20). Вход по паролю, токен только в памяти.
- Запись о постах `posted-lemmy.json` лежит в ветке `brief` (сайт не пересобирается), её ведёт тот же `scripts/nostr-branch.sh` (переменные `STATE_FILE`, `STATE_LABEL`).
- Один пост скидки в день на сообщество. Не прошло в одно сообщество: запуск красный, остальные не дублируются, недостающее получит ТУ ЖЕ скидку при следующем запуске. Статья, не дошедшая в часть сообществ, догоняется 3 дня (`retryDays`).
- Вторая защита от дубля: перед постом программа смотрит новые посты сообщества, и если там уже наш пост с той же страницей, считает его выложенным (даже если запись потерялась).
- Новое сообщество или второй аккаунт = новый элемент в `communities` или новый блок, код не меняется. Для сообщества можно задать `titleTemplate` (формат заголовка, например `[{store}] {title} - {price}`) и `languageId` (английский 37).

## Что может пойти не так
- `check` пишет 403 или «not Lemmy»: сервер за Cloudflare может не пускать запросы с адресов GitHub. Выбрать другой сервер.
- `incorrect_login`, `email_not_verified`, `registration_application_is_pending`: программа пишет, что делать.
- `only_mods_can_post_in_community`, `person_is_banned_from_community`: сообщество выключить.
- `rate_limit_error`: сервер ограничивает частоту, следующий запуск повторит.
- Версия Lemmy 1.0 пока в бете: адреса API v4 взяты из описания, на живом сервере не проверены. Если `check` на 1.0 покажет ошибку, можно задать `apiVersion: "v3"` в настройках.
