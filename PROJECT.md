# SaveAndPlay: паспорт проекта

Обновлено: 6 октября 2026. Положите этот файл в корень проекта (рядом с CLAUDE.md) и начинайте любой новый чат или сессию Claude Code фразой: «Прочитай PROJECT.md». Секретов (паролей, ключей API) здесь нет и быть не должно.

## 1. Что это
Англоязычный сайт и аккаунты со скидками на игры для ПК. Цель: заработок на партнёрских ссылках. Принцип: честные цены, пометка #ad, никакой накрутки.

Роли каналов (решение 6 октября): Bluesky нужен как лицо проекта и источник первых покупателей, но не как гарантированный поток трафика. Данные показали, что голые посты со скидками собирают 1–2 лайка. Лучше работают рубрики с голосом и вкусом, один содержательный пост в день, картинка с alt-текстом, ответы под постами крупных аккаунтов. SEO в план не закладываем. Подробные цифры и список аккаунтов: `SOURCES.md`.

Главная цель на ближайший месяц: получить хотя бы одну настоящую продажу от постороннего человека (в Admitad она появляется как pending вскоре после покупки). Это докажет, что способ раскрутки работает. Деньги и выплаты пока не оцениваем.

## 2. Как устроен сайт
- Папка: `C:\saveandplay` (Astro). Описание и дизайн: `CLAUDE.md`, папка `design`.
- Данные скидок: `data/deals.json`. Дата на сайте берётся из поля `checkedAt`, вручную её не меняем. Файл каждое утро обновляет программа (§11, запись про `update-deals`), вручную только убираем ненужные игры через `exclude` в `data/deals-rules.json`. Перед ручной правкой на компьютере сделать `git pull`.
- Обложки: команда `npm run covers`.
- Выкладка: push в GitHub, GitHub Actions собирает сайт и заливает по FTPS на хостинг Spaceship (`public_html`).
- Страницы: главная, All deals (`/deals/`), страница каждой скидки (`/deals/<магазин>/<название>/`), Guides, Servers, About, Contact, Affiliate disclosure, Privacy, Terms.

## 6. Данные для автоматизации
- Основной источник: товарные фиды самих сетей (GOG: Admitad → Tools → Product Feeds; IndieGala: их фид). Ссылки на фиды хранить только в GitHub Secrets.
- IsThereAnyDeal не используем, пока не проверены его условия: по ним нельзя менять данные и убирать партнёрские метки, комиссия уйдёт им.
- CheapShark: условия использования не подтверждены, его ссылки идут через свой редирект. Не использовать для боевых ссылок.
- «Самая низкая цена за всё время» пока писать нельзя. Копим собственную историю цен (ежедневные снимки в `data/history.json`) и до накопления пишем «lowest price we've tracked».

## 7. План (редакция 6 октября)
Порядок: 1) источники и тематики (`SOURCES.md`, готово) 2) ручной старт: био, закреплённый пост и 14 постов на аккаунт в одном файле 3) через 1–2 недели, если аккаунт ожил, скрипт публикации по расписанию (пароль приложения в GitHub Secrets) 4) позже скрипт черновиков из `deals.json` и истории цен.
Тематики аккаунтов: «Honest prices» (@saveandplay.com, запущен), «Cozy / инди» (лучший отклик по данным), «Retro / DRM-free» (лучше всего подходит GOG). Метки для SubID: `bluesky-prices`, `bluesky-cozy`, `bluesky-retro`.

## 10. Идеи на потом
Раздел «Постеры» (Displate, 25%, подавать напрямую после появления раздела). Раздел «Свой сервер» (WiseHosting 10%, Apex Hosting 15%, Godlike.Host в Admitad). Epic Creator Code при 1000 подписчиков.
Полная автоматизация постов и статей через Claude API в GitHub Actions: программа вызывает Claude по brief, получает черновик поста или статьи и присылает его владельцу на одобрение одной кнопкой (Pull Request или аналог), копировать brief в чат больше не нужно. Отложено 7 октября: у владельца пока нет ключа Anthropic API. Когда появится: ключ только в GitHub Secrets, заранее прикинуть расходы на токены, одобрение человеком оставить.

## 11. Журнал решений
- 6 октября: Twitter/X для проверки трендов недоступен моим инструментам. Тренды берём из RSS (PC Gamer, GamingOnLinux), календаря событий (Wholesome Direct, Next Fest, распродажи) и Bluesky. Вместо X можно присылать скриншоты.
- 6 октября: каталог GOG содержит около 243 игр с тегом cozy, цены в выборке $1,59–14,99. Комиссия с таких игр невысока, поэтому Cozy растим как аудиторию.
- Открыто: запускать ли Cozy и Retro сразу или по очереди, ставить ли партнёрские ссылки в первые посты или через 3–4 дня.
- 6 октября (вечер, ЗАМЕНЕНО записями ниже про один пост в день): владелец хочет, чтобы темы и данные для постов и статей обновлялись автоматически каждый день. Решение: задача по расписанию (раз в день утром по Боготе), которая читает рабочие RSS (PC Gamer, GamingOnLinux) и данные GOG и выдаёт 5–7 тем с причиной «почему сейчас» и черновиком поста. Частота и время ещё не выбраны. Задача только собирает темы, публикует и пишет статьи человек вместе с Claude. Фиды сами по себе к Claude не подключены: без этой задачи их нужно открывать вручную.
- Правило темпа: одна задача за сессию. Уточнение 7 октября: владелец просит не ждать вопроса, а сразу предлагать то, что очевидно нужно проекту и ведёт к автоматизации (например, готовое решение проблемы вместе с текстом для Claude Code). Посторонние идеи, не связанные с целями проекта, по-прежнему не предлагать.
- 7 октября: ГЛАВНЫЙ ПРИНЦИП. Строим рабочую систему, а не ручные шаги. Максимум автоматизации, и каждое решение должно работать для будущих ниш и аккаунтов (настройки в файлах данных вроде `data/accounts.json`, без разовых правок). Владельца нельзя просить делать рутину вручную (копировать, вставлять, загружать картинки, чинить ссылки): если что-то делается руками, это дыра в системе, её надо закрыть кодом или workflow. Если закрыть нельзя, сказать об этом и назвать самый маленький оставшийся ручной шаг. Пример: карточка ссылки в Bluesky решена не ручной картинкой, а страницами игр с Open Graph (см. запись про страницы игр).
- 6 октября (поздний вечер): ежедневный подбор упрощён по просьбе владельца. Сейчас один аккаунт (Honest prices), поэтому один пост в день, а не 5–7 тем. Claude сам выбирает один вариант: скидку GOG или IndieGala и причину «почему сегодня» из новостей. Владелец проверяет только, что в посте есть дата проверки цены и нет ничего странного. Схема: (1) программа на GitHub раз в день читает источники из `data/sources.json` и скидки из `data/deals.json` и пишет маленький файл, без токенов; (2) Claude читает только этот файл и пишет один пост; (3) владелец копирует пост в Bluesky вручную (автопубликация позже, по плану в §7); (4) через 2–4 недели смотрим лайки и вручную меняем источники. Запуск сначала фразой «пост на сегодня», позже по расписанию. Сделано: список источников, программа проверки лент и программа шага 1 (см. запись «ежедневная программа» ниже). Шаг 2 делает Claude по фразе «пост на сегодня»: читает brief и пишет пост.
- 6 октября (поздний вечер): список источников для четырёх тем лежит в `data/sources.json`. Темы: prices (Honest prices), cozy (Cozy и инди), retro (Retro и DRM-free), hardware (хостинг и железо, четвёртый будущий аккаунт, связан с разделом Servers на сайте). В списке 59 записей (кандидатов предложили Gemini, Grok, DeepSeek, Qwen). После первой проверки программой на GitHub 6 октября: 41 работает, 1 редкий, 17 исключены с причиной. ## 12. Для нового чата (состояние на 7 октября, днём)
**Как работать с владельцем.** Он новичок, говорит по-русски. Объяснять просто и коротко, предлагать ОДИН выбранный вариант, одинаковый формат ответов, экономить токены. ГЛАВНЫЙ ПРИНЦИП: не просить владельца делать что-то вручную, строить автоматизацию, пригодную и для других ниш (подробности в §11, запись от 7 октября). Владелец живёт в Колумбии; выплаты: PayPal, Payoneer, банковские счета в Колумбии и Испании (страна выплат не фильтр для программ).

Бриф для поста собирается в 06:00. Все четыре workflow на месте в `.github/workflows` (check-sources, daily-brief, update-deals, deploy).
