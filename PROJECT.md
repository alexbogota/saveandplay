# SaveAndPlay: паспорт проекта

Обновлено: 5 октября 2026. Положите этот файл в корень проекта (рядом с CLAUDE.md) и начинайте любой новый чат или сессию Claude Code фразой: «Прочитай PROJECT.md». Секретов (паролей, ключей API) здесь нет и быть не должно.

## 1. Что это
Англоязычный сайт и аккаунты со скидками на игры для ПК. Цель: заработок на партнёрских ссылках. Принцип: честные цены, пометка #ad, никакой накрутки.

Роли каналов: Bluesky, Pinterest и Telegram приводят людей, сайт их удерживает и ведёт в магазин. По умолчанию пост ведёт на страницу сайта. Часть постов про GOG можно делать с прямой партнёрской ссылкой (SubID `bluesky`) для сравнения результатов через месяц.

## 2. Как устроен сайт
- Папка: `C:\saveandplay` (Astro). Описание и дизайн: `CLAUDE.md`, папка `design`.
- Данные скидок: `data/deals.json`. Дата на сайте берётся из поля `checkedAt`, вручную её не меняем.
- Обложки: команда `npm run covers`.
- Раздел «Servers» (с 5 октября): хаб `/servers/` и три статьи на английском в `src/pages/servers/*.md` (шаблон `src/layouts/Article.astro`). Данные хостинга в `src/lib/hosts.ts`, карточка в `src/components/ProviderCard.astro`; партнёр Godlike.Host (ссылка с `subid=site`). Правила раздела: цифры только из официальных источников со ссылкой на источник и датой; про хостинг пишем только то, что он сам заявляет на своём сайте, с датой проверки; цены не печатаем; не пишем «best» и «we tested», серверы мы не тестировали; бренд Godlike.host не используем в доменах и рекламе, рекламу по бренду не покупаем. Дату в `hosts.ts` (`checkedOn`) и в статьях обновлять при перепроверке.
- Раздел «Guides» (с 6 октября): хаб `/guides/` (`src/pages/guides/index.astro`, список статей внутри файла) и статьи на английском в `src/pages/guides/*.md`. Шаблон тот же `src/layouts/Article.astro`, в начале статьи строка `section: guides` (без неё шаблон считает статью про серверы и добавляет карточку хостинга). Первая статья: «How to tell a real game discount from a fake one» (правила Steam, директива ЕС 2019/2161, ссылки на источники, дата проверки 6 октября). Ссылок на магазины в ней нет, это материал для первых постов в Bluesky и Mastodon. Правила те же: цифры только с источником, «lowest ever» не пишем.
- Превью ссылок в соцсетях (с 6 октября): в `src/layouts/Layout.astro` стоят теги `og:` и `twitter:card`, картинка одна на все страницы: `public/og-image.png` (1200×630, собрана из баннера `drafts/social/banner.png`). Если заменить картинку, соцсети запомнят старую для уже опубликованных постов. Проверять карточку перед постом: вставить ссылку в черновик поста.
- Тема: тёмная (основная) и светлая, переключатель в шапке (кнопка с солнцем или луной). По умолчанию берётся настройка устройства, выбор запоминается в браузере (`sp-theme`). Цвета обеих тем лежат переменными в `src/styles/global.css` (`:root` и `:root[data-theme='light']`). В новых компонентах цвета не прописываем напрямую, только переменные; цвет текста акцента берём `var(--accent-text)`, а не `var(--accent)` (на светлом фоне он темнее).
- Аналитика: Google Analytics 4, Measurement ID `G-7QLYTJ1DJG` (хранится в `src/lib/site.ts`, не секрет). Код в `src/components/Analytics.astro`, баннер в `ConsentBanner.astro`. Для посетителей из ЕС, Великобритании и Швейцарии аналитика включается только после «Accept»; для остальных включена, но можно отказаться. Реклама и её cookie отключены. Выбор хранится в браузере (`sp-consent`), в подвале ссылка «Cookie settings». Клики по «View deal» уходят событием `deal_click` (поля `store`, `deal`); чтобы видеть их в отчётах, в GA4 нужно один раз создать пользовательские параметры (Admin → Custom definitions) `store` и `deal`. Метки в ссылках постов: `utm_source` = bluesky или mastodon, `utm_medium=social`, `utm_campaign=deals-<дата>` (`npm run drafts` делает их сам). Доход смотреть в кабинетах партнёрок по `subid`, в GA он не виден.
- IndieGala на сайте с 5 октября (27 игр, ссылки с `ref=mmu5nmn`). Как обновлять: `npm run indiegala` делает список в `drafts/indiegala.json`, игры переносим в `data/deals.json`, потом `npm run covers`. Скидки IndieGala заканчиваются через 2–11 дней, список нужно обновлять каждую неделю.
- Новый магазин после одобрения партнёрки: записать его в таблицу в разделе 3 (правила каналов, шаблон ссылки), найти источник цен (фид или API), добавить подпись в `src/data/stores.json`, при необходимости добавить его в приоритет дублей в `src/lib/deals.ts`.
- Выкладка: push в GitHub, GitHub Actions собирает сайт и заливает по FTPS на хостинг Spaceship (`public_html`).
- Подписка на рассылку (с 5 октября): сервис Brevo, форма с двойным подтверждением (double opt-in), список «SaveAndPlay Deals». Компонент `src/components/Subscribe.astro` стоит на главной; адрес формы Brevo лежит в `src/lib/site.ts` (`brevoFormUrl`, не секрет). Проверено владельцем 5 октября: подписка, письмо с подтверждением и попадание контакта в список работают. Форма отправляется со страницы через fetch (ответ Brevo прочитать нельзя, поэтому сообщение «проверьте почту» показывается без проверки). Событие `newsletter_signup` уходит в GA4. В Privacy абзац про Brevo добавлен. Перед первой рассылкой: подтвердить домен saveandplay.com в Brevo (записи DNS на Spaceship), указать почтовый адрес компании, проверить шаблон письма с подтверждением (отправитель, английский текст). В письмах: пометка о партнёрских ссылках и ссылка отписки.
- Страницы: главная, About, Contact, Affiliate disclosure, Privacy. Terms ещё нужна.

## 5. Правила публикации
- В каждом посте с партнёрской ссылкой метка #ad. В профилях и описаниях каналов указано, что ссылки партнёрские. Пометку «Automated» (и галочку бота в Mastodon) ставим ДО первого автоматического поста, пока владелец ведёт аккаунты вручную, её нет (решение владельца 5 октября; тексты в `drafts/social/profiles.md`).
- IndieGala (решение владельца, 5 октября): в постах только ссылка на наш сайт. Прямые ссылки с `ref=` в соцсетях не ставим, пока IndieGala не подтвердит правила для соцсетей. В `npm run drafts` для IndieGala прямой ссылки нет.
- Не покупать через свои ссылки.
- Не ставить ссылку магазина туда, где в таблице выше «нет» или «нужно одобрение».
- Любой новый канал сначала добавляется как площадка в Admitad и Sovrn.

## 6. Данные для автоматизации
- Основной источник: товарные фиды самих сетей (GOG: Admitad → Tools → Product Feeds; IndieGala: их фид). Ссылки на фиды хранить только в GitHub Secrets.
- Фид GOG из Admitad не годится для поиска скидок: в нём только обычные цены, без скидок и старой цены, и он давно не обновлялся (в файле дата 9 мая 2026). Годится для списка игр и обычной цены. Скидки GOG пока вносим вручную.
- Фид IndieGala открытый, секретов в нём нет: `https://www.indiegala.com/store_games_rss?sale=true` (500 игр на страницу, `&page=N`, число страниц в теге `totalPages`). В нём есть обычная и новая цена, процент скидки, дата конца скидки, признак DLC, регионы. Рейтингов нет. Почти весь каталог сейчас на недельной распродаже, поэтому скрипт `npm run indiegala` сам отбирает кандидатов: издатель из списка, обычная цена от $30, скидка от 60%, одно издание игры, потом проверка в Steam (от 80% положительных отзывов, от 500 отзывов, без пометок о сексуальном содержании; игры, которых нет в Steam или на которые Steam не ответил, пропускаются). Товары со скидкой «до 2050 года» не берём. Картинки из фида не используем, пока не проверены правила: обложки идут через `npm run covers`.
- IsThereAnyDeal не используем, пока не проверены его условия: по ним нельзя менять данные и убирать партнёрские метки, комиссия уйдёт им.
- CheapShark: условия использования не подтверждены, его ссылки идут через свой редирект. Не использовать для боевых ссылок.
- «Самая низкая цена за всё время» пока писать нельзя. Копим собственную историю цен (ежедневные снимки в `data/history.json`) и до накопления пишем «lowest price we've tracked».

- Проверка по Steam лежит в `scripts/steam.mjs` (сейчас её использует только `npm run indiegala`). Оценки Steam используем только внутри скриптов, на сайте не показываем. Ответы запоминаются в `data/steam-cache.json` на 14 дней, запросы идут с паузой 1,5 секунды. Условия Steam на такие запросы ещё не читали; те же запросы делает `npm run covers`. Позже можно подключить ту же проверку к играм GOG.
- Дубли: если одну игру продают в нескольких магазинах, сайт показывает одну карточку: самую дешёвую, при равной цене GOG, потом IndieGala (`src/lib/deals.ts`). Игра определяется по номеру Steam (поле `steamId` или номер в адресе обложки), иначе по названию. Решение 5 октября: магазины без партнёрки на сайте не показываем. Gamesplanet убран (партнёрки нет, комиссии не будет), разница в цене на $1–2 покупателю не важна.

## 7. План автоматизации
1. Этап 1 (черновики): скрипт собирает скидки из фидов, фильтрует (скидка, рейтинг, без повторов за N дней) и готовит посты и `deals.json`, ничего не публикуя.
2. Этап 2: публикация в Bluesky (пароль приложения в GitHub Secrets), немного постов в день.
3. Этап 3: автообновление сайта по расписанию, дубль в Telegram.
