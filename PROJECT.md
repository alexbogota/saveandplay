# SaveAndPlay: паспорт проекта

Обновлено: 6 октября 2026. Положите этот файл в корень проекта (рядом с CLAUDE.md) и начинайте любой новый чат или сессию Claude Code фразой: «Прочитай PROJECT.md». Секретов (паролей, ключей API) здесь нет и быть не должно.

## 1. Что это
Англоязычный сайт и аккаунты со скидками на игры для ПК. Цель: заработок на партнёрских ссылках. Принцип: честные цены, пометка #ad, никакой накрутки.

Роли каналов (решение 6 октября): Bluesky нужен как лицо проекта и источник первых покупателей, но не как гарантированный поток трафика. Данные показали, что голые посты со скидками собирают 1–2 лайка. Лучше работают рубрики с голосом и вкусом, один содержательный пост в день, картинка с alt-текстом, ответы под постами крупных аккаунтов. SEO в план не закладываем. Подробные цифры и список аккаунтов: `SOURCES.md`.

Главная цель на ближайший месяц: получить хотя бы одну настоящую продажу от постороннего человека (в Admitad она появляется как pending вскоре после покупки). Это докажет, что способ раскрутки работает. Деньги и выплаты пока не оцениваем.

## 2. Как устроен сайт
- Папка: `C:\saveandplay` (Astro). Описание и дизайн: `CLAUDE.md`, папка `design`.
- Данные скидок: `data/deals.json`. Дата на сайте берётся из поля `checkedAt`, вручную её не меняем. Файл каждое утро обновляет программа (§11, запись про `update-deals`), вручную только убираем ненужные игры через `exclude` в `data/deals-rules.json`. Перед ручной правкой на компьютере сделать `git pull`.
- Обложки: команда `npm run covers`.
- Выкладка: push в GitHub, GitHub Actions собирает сайт и заливает по FTPS на хостинг Spaceship (`public_html`).
- Страницы: главная, About, Contact, Affiliate disclosure, Privacy. Terms ещё нужна.

## 5. Правила публикации
- В каждом посте с партнёрской ссылкой метка #ad. В профилях и описаниях каналов указано, что аккаунт автоматизирован и ссылки партнёрские.
- Не покупать через свои ссылки.
- Не ставить ссылку магазина туда, где в таблице выше «нет» или «нужно одобрение».
- Любой новый канал сначала добавляется как площадка в Admitad и Sovrn.

## 6. Данные для автоматизации
- Основной источник: товарные фиды самих сетей (GOG: Admitad → Tools → Product Feeds; IndieGala: их фид). Ссылки на фиды хранить только в GitHub Secrets.
- IsThereAnyDeal не используем, пока не проверены его условия: по ним нельзя менять данные и убирать партнёрские метки, комиссия уйдёт им.
- CheapShark: условия использования не подтверждены, его ссылки идут через свой редирект. Не использовать для боевых ссылок.
- «Самая низкая цена за всё время» пока писать нельзя. Копим собственную историю цен (ежедневные снимки в `data/history.json`) и до накопления пишем «lowest price we've tracked».

## 7. План (редакция 6 октября)
Порядок: 1) источники и тематики (`SOURCES.md`, готово) 2) ручной старт: био, закреплённый пост и 14 постов на аккаунт в одном файле 3) через 1–2 недели, если аккаунт ожил, скрипт публикации по расписанию (пароль приложения в GitHub Secrets) 4) позже скрипт черновиков из `deals.json` и истории цен.
Тематики аккаунтов: «Honest prices» (@saveandplay.com, запущен), «Cozy / инди» (лучший отклик по данным), «Retro / DRM-free» (лучше всего подходит GOG). Метки для SubID: `bluesky-prices`, `bluesky-cozy`, `bluesky-retro`.
Ежедневный подбор материала для поста: `npm run brief` или GitHub → Actions → Daily brief (подробности в §11, запись «ежедневная программа»).
Автоответы на упоминания в Bluesky запрещены правилами, ответы пишет человек. В био аккаунта указываем, что публикации автоматизированы и ссылки партнёрские.

## 11. Журнал решений
- 6 октября: Twitter/X для проверки трендов недоступен моим инструментам. Тренды берём из RSS (PC Gamer, GamingOnLinux), календаря событий (Wholesome Direct, Next Fest, распродажи) и Bluesky. Вместо X можно присылать скриншоты.
- 6 октября: каталог GOG содержит около 243 игр с тегом cozy, цены в выборке $1,59–14,99. Комиссия с таких игр невысока, поэтому Cozy растим как аудиторию.
- Открыто: запускать ли Cozy и Retro сразу или по очереди, ставить ли партнёрские ссылки в первые посты или через 3–4 дня.
- 6 октября (вечер, ЗАМЕНЕНО записями ниже про один пост в день): владелец хочет, чтобы темы и данные для постов и статей обновлялись автоматически каждый день. Решение: задача по расписанию (раз в день утром по Боготе), которая читает рабочие RSS (PC Gamer, GamingOnLinux) и данные GOG и выдаёт 5–7 тем с причиной «почему сейчас» и черновиком поста. Частота и время ещё не выбраны. Задача только собирает темы, публикует и пишет статьи человек вместе с Claude. Фиды сами по себе к Claude не подключены: без этой задачи их нужно открывать вручную.
- Правило темпа: одна задача за сессию, следующую Claude не предлагает, пока владелец не скажет.
- 6 октября (поздний вечер): ежедневный подбор упрощён по просьбе владельца. Сейчас один аккаунт (Honest prices), поэтому один пост в день, а не 5–7 тем. Claude сам выбирает один вариант: скидку GOG или IndieGala и причину «почему сегодня» из новостей. Владелец проверяет только, что в посте есть дата проверки цены и нет ничего странного. Схема: (1) программа на GitHub раз в день читает источники из `data/sources.json` и скидки из `data/deals.json` и пишет маленький файл, без токенов; (2) Claude читает только этот файл и пишет один пост; (3) владелец копирует пост в Bluesky вручную (автопубликация позже, по плану в §7); (4) через 2–4 недели смотрим лайки и вручную меняем источники. Запуск сначала фразой «пост на сегодня», позже по расписанию. Сделано: список источников, программа проверки лент и программа шага 1 (см. запись «ежедневная программа» ниже). Шаг 2 делает Claude по фразе «пост на сегодня»: читает brief и пишет пост.
- 6 октября (поздний вечер): список источников для четырёх тем лежит в `data/sources.json`. Темы: prices (Honest prices), cozy (Cozy и инди), retro (Retro и DRM-free), hardware (хостинг и железо, четвёртый будущий аккаунт, связан с разделом Servers на сайте). В списке 59 записей (кандидатов предложили Gemini, Grok, DeepSeek, Qwen). После первой проверки программой на GitHub 6 октября: 41 работает, 1 редкий, 17 исключены с причиной. Проверка всех лент: `npm run sources` или GitHub → Actions → Check sources → Run workflow (таблица на странице запуска, раздел Summary). Программа только читает RSS, уважает robots.txt и представляется честным User-Agent.
- 6 октября (поздний вечер): выводы по источникам после проверки программой на GitHub (Actions → Check sources). Из 54 лент работают 40 (плюс GOG), 6 давно не обновляются, 2 не RSS, 5 закрыты (403 или 404). Метки «verified» у других ИИ были ненадёжны: часть ссылок оказалась мёртвой, а часть сайтов, закрытых для инструмента Claude (Rock Paper Shotgun, Eurogamer, Polygon, LadiesGamers), на GitHub открылась. У GOG ЕСТЬ лента новостей `https://www.gog.com/frontpage/rss`: релизы и DLC без скидок, это те игры, на которые у нас есть партнёрская ссылка. Статус «нет дат» у неё был багом программы (даты в формате EEST), исправлено. Reddit в проверку не брали: он не открылся ни инструменту Claude, ни двум ИИ. Работающих источников по темам: prices 11, cozy 18, retro 11, hardware 11 (часть входит в несколько тем). Но у крупных лент 80–180 записей в неделю (Polygon, gg.deals News, KitGuru, Phoronix, PC Gamer), поэтому нужен фильтр по ключевым словам. Другие ИИ используем только для поиска кандидатов, проверку делает программа.
- 6 октября (поздний вечер): инструмент WebFetch у Claude просит разрешения владельца на каждый новый адрес из ответов других ИИ. Не слать десятки адресов сразу: запросы сгорают, если владельца нет рядом. Массовую проверку делаем программой на GitHub.
- 6 октября (поздний вечер): ежедневная программа сделана (шаг 1 схемы). Запуск: `npm run brief` или GitHub → Actions → Daily brief (сама каждое утро в 06:00 по Боготе, или кнопка Run workflow). Как работает: читает источники из `data/sources.json` (только с темой аккаунта, статус ok или rare), берёт новости за последние 48 часов, сопоставляет их со скидками из `data/deals.json` (по ссылке на страницу игры в Steam или GOG внутри новости, либо по названию в заголовке; продолжения вроде «Evolution 2» не считаются; названия из одного короткого слова вроде Control находятся только по ссылке) и пишет `drafts/brief-<аккаунт>.md`, около 1 000 токенов: до 5 вариантов с оценкой, причиной «почему сегодня» (сколько независимых сайтов написало, акция скоро закончится, самая низкая цена по нашей истории, место по размеру скидки), готовой ссылкой (GOG: партнёрская с SubID аккаунта, IndieGala: ссылка на наш сайт с UTM) и правилами поста. Claude берёт первый вариант и пишет один пост. Правила отбора: магазины GOG и IndieGala, скидка от 50%, цена проверена не позже 48 часов назад, акция не кончается раньше чем через 6 часов, игра из прошлых вариантов (память 7 дней) получает штраф. Скидки без новостей тоже попадают в список (по цене), так что материал есть каждый день. Новости GOG про игры без скидки идут отдельным пунктом без цены. Результат виден на странице запуска (раздел Summary, блок для копирования) и сохраняется в ветку `brief` (не main, сайт не пересобирается; каждый день один коммит, это архив). Код: `scripts/daily-brief.mjs`, общий код чтения лент `scripts/lib/feeds.mjs` (его же использует `check-sources.mjs`), сопоставление названий `scripts/lib/titles.mjs`, ветка `scripts/brief-branch.sh`, расписание `.github/workflows/daily-brief.yml`.
- 6 октября (поздний вечер): как добавить аккаунт. Открыть `data/accounts.json`, скопировать блок `prices`, поменять ключ (например `cozy`), `name`, `handle`, `topic` (одна из тем в `data/sources.json`), `subid` (например `bluesky-cozy`), `stores` и правила. Поля, которые не указаны, берутся по умолчанию (описание всех полей в `about` внутри файла). Код менять не нужно: источники по теме подхватятся сами, каждая лента читается один раз за запуск, даже если её используют несколько аккаунтов. Для аккаунтов, где скидка не главное, ставим `dealsWithoutNews: false` и список `keywords`: тогда в brief попадают новости с этими словами в заголовке и только те скидки, о которых написали источники.
- 6 октября (поздний вечер): что не закрыто в ежедневной программе. (1) и (2), цены и история цен, закрыты записью про `update-deals` ниже. (3) Brief пока вставляется в чат вручную: репозиторий закрытый, а GitHub к Claude не подключён. Если подключить GitHub в настройках Claude, Claude сможет читать ветку `brief` сам. (4) Память о повторах: программа считает «предложенным» первый вариант каждого дня, а не тот пост, который реально опубликован.
- 7 октября (ночь): цены обновляются сами. Программа `scripts/update-deals.mjs` (`npm run update-deals`, пробный запуск `npm run update-deals -- --dry-run`; GitHub → Actions → Update deals, сама каждое утро в 04:30 по Боготе) обновляет `data/deals.json` и `data/history.json`. IndieGala: запускает `scripts/indiegala-candidates.mjs` (открытая лента скидок IndieGala и прежние правила: известный издатель, скидка от 60%, отзывы в Steam) и берёт его список целиком как новые скидки IndieGala; найденные обложки сохраняются. GOG: у каждой игры GOG из файла спрашивает текущую цену в открытом каталоге GOG (`catalog.gog.com`: поиск по названию, игра узнаётся по имени в адресе), берёт дату конца акции со страницы игры (строка «Offer ends on»), убирает игры, у которых скидка кончилась (стала меньше 30%), и добавляет до 6 новых за запуск из самых продаваемых скидок: скидка от 50%, старая цена от $9,99, от 300 отзывов на GOG и рейтинг от 3,8 звезды, затем та же проверка Steam, что у IndieGala (от 500 отзывов, 80% положительных, без флагов взрослого контента). Всего игр GOG не больше 24, новых от одного издателя не больше 3. api.gog.com не используем: он закрыт для программ правилами сайта (robots.txt). После этого: игры из `exclude` в `data/deals-rules.json` убираются, запись с ценой старше 48 часов убирается (лучше показать меньше, чем старую цену), на каждый день сохраняется снимок цен. Дальше workflow заполняет обложки новых игр (`npm run covers`), сохраняет файлы в main (коммит от `saveandplay-bot`) и запускает выкладку сайта. Если магазин не ответил, его старые записи остаются как были (и пропадают через 48 часов); если не ответили оба, файлы не меняются, а запуск помечается красным. Все пороги и их описание: `data/deals-rules.json`, поле `about`. Общий код GOG: `scripts/lib/gog.mjs`.
- 7 октября (ночь): что важно знать про `update-deals`. (1) Теперь `data/deals.json` и `data/history.json` меняет бот. Перед ручной правкой на компьютере сделать `git pull`; если push не проходит, `git pull --rebase` и повторить. `npm run drafts` на компьютере для истории цен больше не нужен. (2) Из облачной песочницы GOG и IndieGala недоступны, поэтому программа проверена на имитации и на примерах ответов каталога GOG (поиск по 7 сложным названиям нашёл все игры). Формат даты конца акции на странице GOG проверен только по тексту страницы. Первый запуск на GitHub покажет, всё ли разобрано: смотреть таблицу в Summary (строки «не удалось уточнить»). Если даты конца акции не находятся, записи остаются без `endsAt`, программа это сообщит. (3) Сайт показывает одну дату «Prices last checked» по самой свежей записи. Если один магазин не ответил, его записи могут быть старше этой даты, но не больше 48 часов.
