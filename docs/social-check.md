# Проверка «выложен ли пост к гиду»

Решение владельца 14 октября 2026: владелец копирует пост и публикует сам, но НИКОГО не уведомляет, что он выложил. Раньше из-за этого в отчётах вечно висело «выложить посты к гидам», хотя они давно были в ленте. Теперь это считает программа, ничего писать не нужно.

## Как это работает
- `npm run social:pending` (программа `scripts/social-pending.mjs`, настройки `data/social-check.json`). Читает ПУБЛИЧНУЮ ленту нашего аккаунта (пароль не нужен, ничего не публикует и не меняет).
- Гиды берутся из `src/pages/guides/*.md` (дата из строки `updated`). Гид считается выложенным, если в одном из НАШИХ постов (не ответ, не репост чужого) есть ссылка `saveandplay.com/guides/<slug>`: в тексте, в ссылке-карточке или в самом посте. Метки `?utm_...` не мешают.
- Bluesky: хэндл берётся из `data/accounts.json` (`accounts.prices.handle`), читаются последние 300 постов.
- Mastodon: аккаунт указан в `data/social-check.json` (`mastodon.instance` = mastodon.social, `mastodon.acct` = saveandplay, указал владелец 14 октября). Если поля пустые, программа пишет «Mastodon не настроен» и ничего о нём не утверждает.
- Честность: если ленту не удалось прочитать, программа пишет «не удалось проверить», а не «не выложен». Если гид старше того куска ленты, который прочитан, пишет «слишком старый для проверки».
- Итоговая строка `WAITING FOR A POST: ...` перечисляет, чего не хватает. `--json` даёт то же для программ. Убрать гид из проверки: его slug в `ignore`.
- Как пользоваться в отчётах: пункт «выложить посты к гидам» брать только из этого результата, а не из старой записи в START.md.

## Проверка
- `npm run social:test`: 8 проверок на тестовом сервере (формы ссылок, чужие и повторные посты, старые гиды, Mastodon, ленту, которая не открылась, командная строка). Проверено, что тесты краснеют, если сломать правило.
- Формат ответа Bluesky сверен с настоящей лентой аккаунта 14 октября: ссылки на гиды лежат и в facets, и в embed.external, оба места читаются.
- Mastodon сверён с настоящим аккаунтом 14 октября: имя находится, публичные статусы читаются, ссылки на гиды лежат и в тексте, и в карточке. На 14 октября оба аккаунта показывают одно и то же: выложены 4 гида из 5, нет гида про возвраты Steam (владелец пока не выкладывает его, плана нет).
- Живой запуск самой программы (`npm run social:pending`) с компьютера владельца ещё не делался: формат ответов сверен по настоящим данным, но сверку делал чат, у которого нет прямого выхода в эти API.
